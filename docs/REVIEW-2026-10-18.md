# Fo Reach version 4 review — 2026-10-18

This review covers the cloud source in `/workspace/wajo-hack`, including the web interface, local repair engine, HTTP/stdio MCP, owner authentication, bounded device relay, macOS source and deployment templates. Independent functional and security reviewers reproduced concrete defects and reviewed the fixes. Every successful repair in this review used explicitly synthetic fixtures. No account, actual device, paid model or public deployment was contacted or changed.

The product is **Fo Reach**; `fo-reach.latchgrid.in` is the planned hostname. This review did not provision DNS or TLS. The implemented vertical slice remains sound-output selection and unmuting with specific local approval, fresh-read setting verification and separately approved undo. File transfer is not implemented. Legacy `FO_FIX_*`, `fo_fix_*`, `.fo-fix`, package/executable paths and the status protocol name `Fo Fix` remain compatible with version 4.

## Additional checks and observed failure

`node deploy/gcp/offline-check.mjs` passed again: synthetic owner/MCP separation, anonymous and CSRF rejection, proxy header guards, mode-0600 SQLite, persisted history, restart revocation, mount guard and local systemd syntax. [gcp-offline-checks.json](gcp-offline-checks.json) records the limits: Caddy's parser is unavailable; no cloud resource, real mount or public TLS was exercised.

The first expanded browser run passed 11 checks and timed out in the new long-name regression because its fixed target was already the active output left by an earlier test. The test setup now chooses an inactive synthetic output. Its isolated rerun passed. A later full check caught a branding edit to the startup readiness log that existing lifecycle/deployment checks parse. That edit was reverted; the legacy readiness line remains compatible. Another run exposed reuse of a stale fetch keep-alive socket as device-session tests rapidly restarted companions on one fixed port. Their test helper now allocates a fresh ephemeral port for each companion. The subsequent complete suite passed. All three failing logs are retained in the review bundle; they were not represented as clean first runs.

`npm run macos:build` exited 1 with “The CoreAudio helper can only compile on macOS.” This correctly exercises the platform guard and is **not** a native compilation pass. No `swiftc` or macOS hardware is available here.

Independent follow-up checks found the reported defects resolved: 30 engine/MCP checks, one targeted malformed-result check, six native wire checks and two ephemeral HTTP bridge probes. They found no further actionable defect in these fixes; this is not a certification or a claim that every possible defect is absent.

## Reconciliation and remaining integration work

The delivery includes a standard Git patch against the preserved version 4 source and a SHA-256 manifest for every source file, plus a replay check showing that applying the patch to a clean extracted baseline reproduces the reviewed source. Apply the patch only after checking the baseline. A separately modified deployment copy must reconcile overlapping edits instead of blindly overwriting them. The review does not assume the blocked cross-environment transfer has become available.

The cloud code and synthetic end-to-end path are working. Still required: macOS compilation, permissions and actual device/physical audibility tests; real HTTPS/proxy/runtime acceptance; and user-authorized Fo registration/credential entry. The existing Fo account connector is separate from this custom MCP server. Registration guidance uses the parent's verified current Fo catalogue (`streamable_http`, explicit `bearer`, personal scope, secure credential form after registration); no registration was attempted in this run. Optional OAuth remains unverified with live Fo.

The same-OS-user trust boundary, owner-editable local journal, CoreAudio's lack of atomic compare-and-swap, uncertain abruptly interrupted writes and single-owner/single-process scope remain documented. No credentials, persistent access, service purchases, remote pushes or public deployment were created by this review.
